## 1. 一句话结论

ChromeDebloater 这一类工具（C++ 原生、管理员常驻、全系统硬化）与面板（便携、可逆、零依赖、单文件）是同一问题的两种解法：**工程结构上值得学的是它们的手艺（保留策略、自描述备份、指纹跳过、清单分级），功能上它们对 Edge 158 没有可直接抄的有效去臃肿条目**。

## 2. 已被实测推翻的两个旧结论（最重要，别复发）

### 2.1 "基线有 8 条僵尸策略，写了 Edge 不认" —— 不成立

- **旧依据**：把微软官方策略主表（804 条）+ 废弃段（26 条）当全集做差集，查不到即判"僵尸"。
- **真相**：本机 `edge://policy` 导出 132 条，与基线 132 条一一对应；那 8 条（`AADWebSSOAllowed`、`CopilotMode`、`CopilotMultitabEnabled`、`CopilotPageContextEnabled`、`EdgeAdminCenterEnabled`、`EdgeEntraCopilotPageContextIncludesHistory`、`HighEfficiencyModeEnabled`、`PasswordDismissCompromisedAlertEnabled`）全部在列、`level=mandatory`、被 Edge 实际接受。
- **规则**：判断策略"是否存在/是否生效"的唯一权威是 `edge://policy` 及其导出 JSON；微软文档只能查"有效版本区间"。

### 2.2 "从它那里能抄 6 条去臃肿策略" —— 6/6 全是 Obsolete

逐条打开官方详情页核对 `Supported versions` 后：`EdgeCollectionsEnabled`(78–152)、`EdgeEnhanceImagesEnabled`(97–121)、`EdgeFollowEnabled`(98–126)、`MathSolverEnabled`(91–125)、`DiscoverPageContextEnabled`(113–127)、`MetricsReportingEnabled`(77–88) 全部已下线。**错因**：只看总目录页（804 条里混着 obsolete，且没有状态列）。

| 机制 | 出处 | 本项目的处置 | 落在哪 |
|---|---|---|---|
| 备份保留份数（日期名 + keep-N） | CentBrowser / ludusavi | ✅ 已做：默认 3 份、可填 1–9，手动与自动备份共用同一额度 | 备份弹窗「保留最近 N 份」 |

| 结构漂移检测（快照比对） | 无同类，自研 | ✅ 已做：只在更新链路跑；瘦身后的本地目录不能当基线（否则报 400 条假差异） | F9（`.130`） |

## 4. 明确不借鉴的实现方式（附理由）

| 项 | 为什么不学 |
|---|---|
| hosts 屏蔽遥测域 + 防火墙出站规则 | 影响面溢出到系统其它浏览器/组件，与"便携、可逆"定位冲突 |
| `requireAdministrator` 常驻管理员 | 本项目按需提权；常驻 = 任何一处 bug 都是系统级 |
| 游戏模式 flags（关帧率限制 / 关 vsync） | 破坏 GPU 稳定性与省电，属性能玄学 |
| 直接改浏览器 `Local State` / `Preferences` | 版本升级会重写、可能被校验；同样效果用组策略就能拿 |
| 大窗口 + 多页导航 | 与"一屏看清"偏好相反，125% 缩放下会溢出 |
| 用 C++ 重写换 402 KB 体积 | 体积不是痛点（其中 900 KB 是内嵌脚本），重写会丢掉"改一行不用编译"的迭代速度 |
