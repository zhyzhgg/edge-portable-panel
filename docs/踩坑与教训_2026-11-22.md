# 踩过的坑与教训

便携 Edge 面板 v1.3.4 → v1.3.5 期间（24 个解包键）犯错、返工、两次把开发机桌面搞挂的复盘。
每条只写三样东西：**看到什么现象、当初错在哪、今后按什么规则做**。
配套文档：界面规范见 `GUI规范_WinForms_v2_2026-11-22.md`。

---

## A 判断与验证

### A1 拿外部文档当全集，误删了有效策略

| | |
|---|---|
| **现象** | 把 8 条策略判成"僵尸"（以为 Edge 不认），准备在基线里标 `remove`、应用时删注册表旧值 |
| **错因** | 抓微软官方文档（主表 804 条 + 废弃段 26 条）做集合运算，查不到就推断"Edge 不认" |
| **真相** | 微软文档不是完整白名单。`edge://policy` 实测：8 条全部在列、状态"确定"、等级"强制"，页面没有任何"未知策略"区块 |

**规则**

1. 判断策略是否存在或生效，唯一权威是 `edge://policy` 及其导出 JSON；微软文档只能查"有效版本区间"。
2. 禁止凭外部文档差集生成删除动作。下线过期策略只走「单条 `remove`」（必须官方详情页明确写 obsolete 才允许），**不要再用 `maxMajor` 这类版本判断机制**（`.228` 已整体移除）——"这条不写/只删这一条"的风险远小于"凭差集拆掉一批有效保护"；只有实测报 `Unknown policy` 或明确导致故障，才允许从基线删条目。

### A2 统计口径漏了一类记录，误报基线缺两条

| | |
|---|---|
| **现象** | 比对导出的 132 条，断言基线缺 `CookiesAllowedForUrls` 与 `URLBlocklist` |
| **错因** | 用 `Where-Object { -not $_.sub }` 只取 130 条主策略去比 |
| **真相** | 那 2 条一直在基线里，以子键项形式存在（`sub` 字段 + 值为 `1`），注册表侧是子键下一个 `String`，不是多字符串 |

**规则**：核对脚本一律按 `if ($_.sub) { $_.sub } else { $_.name }` 取全集去重，不要用 `-not $_.sub` 只取主策略。

### A3 把"应该等宽"当成"确实等宽"，没量就写进代码

| | |
|---|---|
| **现象** | 日志级别列用两个 `U+2500`（`──`）当占位符，以为和两个汉字等宽 |
| **真相** | 实测雅黑 8.5pt：`完成`/`警告`/`失败` 各 39 px，`──` 只有 31 px，竖线左移 8 px |

**规则**：任何"应该一样宽、一样高、居中对齐"的视觉假设，先用 `TextRenderer.MeasureText` 量再写代码。当前四档统一用两个全角汉字（完成/警告/失败/信息），前缀均为 139 px。

### A4 目视看起来齐，不等于量出来齐

| | |
|---|---|
| **现象** | 顶栏 GitHub 与反馈的垂直位置来回改了三轮（加 1 px、加 2 px、最后减 1 px） |
| **错因** | 以为控件框对齐就等于视觉对齐 |
| **真相** | 控件框 Top/Height/TextAlign 全一致时，雅黑中文墨迹比拉丁字母整体偏高（中文 137 至 166，拉丁 142 至 169），视觉仍差 2 至 4 px |

**规则**：对齐类问题一律截图像素扫描墨迹上下界，用墨迹底部（基线）判齐，别用控件中心推断。当前三者基线已精确对齐，误差 0 px。

### A5 手绘图标永远不像，三轮都被否

| | |
|---|---|
| **现象** | 三次否决："太离谱了完全不对"、"缺了小猫的手"、"不太像" |
| **错因** | 自己造"圆脸加两耳加两侧手"，以为 14 px 下够用 |
| **真相** | 14 至 18 px 下手绘简化路径不可能还原品牌轮廓，画出来糊成一团，侧边的手还被看成第二对耳朵 |

**规则**：品牌图标一律用官方矢量路径（octicons 的 mark-github-16 或 24），用 SVG path 转 GDI+ `GraphicsPath`（含椭圆弧转贝塞尔）。位图缩放跨进程 UIA 都是下策。

### A6 视觉细节由评审拍板

| | |
|---|---|
| **现象** | 擅自把日志前缀改成方括号加空格，被评审否掉（"不喜欢这种风格"） |

**规则**：被否掉过的样式，不要换个说法再来一次；样式改动先给方案和理由，等确认为准。

## B 代码与路径

### B1 改一处路径，另一处忘改，快路径静默失效六个版本

| | |
|---|---|
| **现象** | 点"打开策略管理"一直走慢路径，多花约 2.5 秒，持续了六个版本没人发现 |
| **错因** | 把中文副本从解包目录搬到共享目录时，只改了 run-zh.ps1，面板里算 out.ps1 路径的那行没动；新路径不存在，快路径判定恒为假 |

**规则**

1. 跨文件共享路径必须双向核对：改 run-zh 的 `$work` 就看面板的 `$outPs1`，反之亦然。
2. 根治靠抽唯一事实源：`_Common.ps1` 里的 `Get-ZhWorkDir()`，两边都调它（已落地，两处硬编码清零）。

### B2 快路径跳过的脚本，它的副作用必须由跳过方补做

| | |
|---|---|
| **现象** | 快路径直接拉起 out.ps1，跳过了整个 run-zh，于是漏掉 run-zh 第 3 步"复制 chrome++.ini" |
| **后果** | out.ps1 靠同目录的 chrome++.ini 读 policy_key，文件过期会读写到错误的注册表键 |

**规则**：做短路优化时，先列出被跳过脚本的全部副作用，把必需的（配置同步、目录准备、锁获取）在快路径里补做。

### B3 文件读写的相对路径按进程当前目录解析，不认 cd

| | |
|---|---|
| **现象** | 同一个坑踩了两次。脚本里读 `docs\xxx.md` 解析到了工作区根而不是项目目录，写入失败；早前还因此在工作区根留下一个 3 字节的空 ps1 |

**规则**：脚本与临时命令里一律用绝对路径（`Join-Path $PSScriptRoot ...` 或写全）。`Get-Content`、`Set-Content` 走 PowerShell 路径解析，行为与 .NET 方法不同，别混着推理。

### B4 改 PowerShell 脚本的四件套

1. `Start-Process -ArgumentList` 的数组元素不会自动加引号，含空格路径必须自己包引号。
2. `edit` 工具会剥掉 BOM，改完必须补回。
3. 改完必须"去掉所有回车再统一成 CRLF"，否则 git 会把整文件算成改动。
4. 改脚本必须跑 `build.ps1 -Bump`（校验 BOM、PS 5.1 语法、版本三方一致）。

### B5 部署前必须先杀掉占用者

| | |
|---|---|
| **现象** | 复制报"文件被另一进程占用"，因为面板宿主常驻、占着目标文件；还有一次复制失败但冒烟照跑，实际测的是旧版 |

**规则**：部署前先结束面板宿主与带面板标题的子 PowerShell 进程；复制之后再校验一次目标文件哈希。

### B7 同一套过滤逻辑写在两处，改一处漏一处

| | |
|---|---|
| **现象** | v1.3.5 发布后才发现：策略版本过滤只加在「应用推荐策略」里，漂移检查没加 |
| **后果** | 当前 Edge 158 不发作；等 Edge 159 来了，每次开面板都会红字报「基线里有 1 条注册表缺失 → 点应用补回」，点了应用把它删掉后又立刻报缺失，陷入死循环 |
| **真相** | 过滤条件（`remove` 与 `maxMajor` 超期）被写了两遍：`Apply-RecommendedPolicies` 的 `$activeRecs`/`$dropRecs` 有，`Get-PolicyDrift` 的 `$flatBase` 没有 |

**规则**

1. 凡是「该写哪些条目」这种判定，**只能有一个函数产出它**，写入方与校验方都调它（例如抽 `Get-ActiveBaselineRecords`）。写两遍必然漂移。
2. 改动这类判定时，先全局搜索同名条件（`maxMajor`、`remove`、`$_.sub`），确认所有使用点都跟上了。
3. 修完要**用未来状态验证**：不只测当前版本，还要模拟「版本跨过 maxMajor 之后」的行为（那次就是靠离线模拟 Edge 159 才确认的）。

### B6 每次 Bump 都是一档，索引漏一行就像跳号

| | |
|---|---|
| **现象** | 曾有人问"怎么从 214 直接跳到 216"。实际没跳号：213 构建成功但部署时文件被占用没换成，214 重建；215 是回退；216 修回归。但文档索引漏写了 215 那一行 |

**规则**：改动索引每个解包键一行，不许把两档折进一行；文档里注明解包键是连续递增的。

## C 把开发机搞挂的两次

### C1 第一次：高频起杀图形界面进程

当时在做什么：累计让面板"起—杀"约 16 至 18 次（5 次界面体检每次 2 个实例，加 4 次截图脚本，加 2 次 UIA 测量），每次都用强制结束杀掉承载 WinForms 的 PowerShell。

直接诱因：高频强杀图形进程，资源管理器的窗口枚举与 Shell 钩子反复重挂。系统日志里 18:49:58 记录 `explorer.exe` 停止响应。

放大器：体检脚本里有个函数会遍历全系统 PowerShell 进程、按命令行匹配面板脚本强杀——连本机正在使用的面板一起杀。

### C2 第二次：UI Automation 枚举整个桌面，把资源管理器拖死

这次有代码与日志双向对上。体检脚本定位窗口用 `RootElement.FindAll` 枚举整个桌面的顶层窗口，每 250 毫秒一轮、上限 25 秒，合计 100 轮。这个调用会对系统上每一个窗口所在进程发跨进程 UIA 请求。

那一次 1.25 倍档"没等到窗口"，循环完整跑满 100 轮；而这一轮跑了 6 次体检，累计 500 至 600 轮全桌面枚举。结果是资源管理器的 UIA 提供程序被拖死，连带着几个第三方工具一起挂起（系统日志 19:10:02 与 19:10:09 两条停止响应）。

**一开始归因错了**：先怪"反复强杀"，实际真凶是 UIA 全桌面枚举。纠正的方法是——两次死机挂的都是资源管理器而不是面板，那就该怀疑"谁在跨进程查询资源管理器"。

### C3 由此确立的界面验收铁律

1. 严禁用 `RootElement.FindAll`（任何范围）。定位窗口只能用 Win32 的 `EnumWindows` 加 `GetWindowThreadProcessId`，按自己启动的进程号（含宿主与子 PowerShell）匹配。
2. 只对找到的那一个窗口句柄做 `AutomationElement.FromHandle` 内部遍历。
3. 轮询间隔 250 毫秒改 500 毫秒，上限 25 秒改 15 秒。
4. 提供 `-NoUia` 开关：零 UIA 调用，只做 Win32 几何与截图。
5. 只杀自己启动的进程号（启动返回的号加一次父子查询），绝不按名字或命令行全局匹配。
6. 关闭优先走优雅路径：`CloseMainWindow()` 等 3 秒，仍未退出才强制结束。
7. 截图类验证必须关掉网络探测：设 `EP_NO_PROMPT=1` 与 `EP_NO_PANEL_PROBE=1`，否则每个实例都发 6 路 HTTPS，无代理时各卡 8 秒。
8. 跑完必须查残留：面板进程数、带标题的 PowerShell 数、资源管理器是否健在、近 5 分钟有无"停止响应"事件。
9. 验收不要反复启停图形界面：一次构建只跑一次体检；截图用它自己存的那张，不要再写脚本另起窗口。

## D 网络与探测

### D1 启动时的静默探测最坏阻塞 48 秒且不可中断

| | |
|---|---|
| **现象** | 启动探测串行试 6 个源（3 个 releases 加 3 个 API），每个超时 8 秒，最坏 48 秒；用的是同步 GetResponse，BeginStop 中断不了正在执行的 .NET 调用 |
| **后果** | 没开代理时正常使用面板，GitHub 直连被重置，6 路连接全卡在超时上 |

**已修**：单源超时 8 秒改 2.5 秒，源从 3 个减到 2 个（去掉常连不上的 ghfast），加总预算硬上限 8 秒，改用可中断的异步请求（关窗时置取消标记立即中止），并加 30 分钟本地缓存（临时文件加原子复制覆盖写）。

### D2 推送常被重置，但 API 是通的

**规则**：先试直连，失败换代理参数（代理不一定常开），两者都失败就隔一会儿重试。`gh api` 一直可用（已登录），不要用匿名 API——每小时 60 次极易耗尽。

另一条：本地工作副本与公开仓库是两个独立仓库，提交号天然不同，核对同步要按文件哈希比，别比提交号。

## E 文档与工程习惯

### E1 用脚本批量替换 markdown 会造出重复章节

| | |
|---|---|
| **现象** | 权威文档一度出现两套四章到六章、附录插到六章中间 |
| **错因** | 替换锚点在文中出现两次，脚本只改了第一处，后续插入位置全错 |

**规则**：脚本改文档后必须重新核对章节结构（标题列表是否连续、有无重复）；锚点要选唯一的；大改宁可就整篇重写。

### E2 同一信息只留一份

| | |
|---|---|
| **现象** | 曾把"本版全部改动"同时写进三章与六章，立刻造成重复 |

**规则**：发现重复当场合并。那次把六章那张表改成指向三章，并给三章标注"唯一清单"。

### E3 发版前测试清单固定五项，不能挑着跑

1. `build.ps1 -Bump`（BOM、语法、版本三方一致）。
2. `-RunOnce Status` 冒烟（无窗口、无 UIA、无探测）。
3. 回归十五项（公共函数）。
4. 回归十二项（瘦身 proxy 归位）。
5. 界面体检（一倍与一点二五倍两档）。

这次的教训：曾以"怕再死机"为由跳过第五项，被评审当场问"不用把之前每次都做的测试再跑一遍吗"。正确做法是把工具修好再跑，不是跳过。

### E4 体检控件数从 64 降到 52 是已知取舍

新工具不再经资源管理器的 UIA 代理（那正是死机元凶），跨进程拿到的调用拿到的是简化视图：元素类型全是 Pane、数量少 12 个。位置、越界、重叠检查仍有效，损失的是类型标签。要恢复 64 只能回老路，等于把死机根因请回来，不做。

## F 一页速查

| 场景 | 一句话规则 |
|---|---|
| 判断策略是否有效 | 只看 edge://policy 导出，不看微软文档 |
| 基线统计 | 用 sub 有值取 sub、否则取 name，取全集 |
| 对齐、等宽、尺寸 | 先量再写代码 |
| 品牌图标 | 用官方 SVG 转 GraphicsPath，别手绘 |
| 跨文件路径 | 双向核对，最好抽到 _Common 做唯一事实源 |
| 做短路或快路径 | 先列出被跳过脚本的全部副作用并补做 |
| 文件读写 | 绝对路径，.NET 方法不认 cd |
| 改完脚本 | 补 BOM、统一 CRLF、跑 Bump |
| 部署 EXE | 先杀宿主与子进程，复制后再验哈希 |
| 界面自动化 | 只查自己进程号的窗口，绝不枚举全桌面 |
| 跑界面验收 | 关探测、优雅关闭、查残留、一次就好 |
| 启动网络探测 | 单源 2.5 秒、总预算 8 秒、可中断、带缓存 |
| 文档批量替换 | 锚点唯一，改完核对章节结构 |
| 发版测试 | 五项全跑，不许挑 |
| 判定条件（该写哪些条目） | 只留一个函数产出，写入方与校验方共用 |
